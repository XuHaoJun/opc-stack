# auth — better-auth (email + password)

Adds session-based auth on top of the `nextjs` base, using the base's raw `pg`
pool. No ORM: better-auth talks to the same Pool `lib/db.mjs` already exports.

```sh
prototype layer add <name> auth
node scripts/migrate.mjs      # applies the generated auth schema
```

## Using it

Server side (route handlers, server components):

```js
import { auth } from "@/lib/auth.js";
const session = await auth.api.getSession({ headers: await headers() });
```

Client side:

```js
import { signIn, signUp, signOut, useSession } from "@/lib/auth-client.js";
```

The HTTP endpoints are live immediately — you can exercise them before building
any UI:

```sh
curl -X POST -H 'Content-Type: application/json' \
  -d '{"email":"a@b.test","password":"hunter2hunter2","name":"T"}' \
  "$DEV_URL/api/auth/sign-up/email"
```

## What it does, and why

1. `pnpm add better-auth`.
2. `lib/auth.js` — `database: pool`, reusing the base's pg pool. better-auth
   accepts a `pg` Pool directly; the ORM in most tutorials is not required.
3. `app/api/auth/[...all]/route.js` — the catch-all handler.
4. `lib/auth-client.js` — **no `baseURL`**. The client defaults to the current
   origin, which is what you want when the preview is published under a host
   that is not localhost and can change.
5. `BETTER_AUTH_SECRET` (generated once) and `BETTER_AUTH_URL` (from `DEV_URL`)
   appended to `.env`. Without the URL, better-auth derives its origin from the
   incoming request and warns that callbacks and redirects may misbehave.
6. The schema is generated by `@better-auth/cli` into `migrations/` as an
   ordinary numbered migration — so it goes through the same runner as
   everything else instead of being a second, parallel migration mechanism.

## Notes

- Re-running is a no-op (it checks for `lib/auth.js`).
- `BETTER_AUTH_SECRET` lives in `.env`, which is gitignored and survives
  re-provisioning. If `.env` is ever lost, existing sessions become invalid —
  fine for a prototype, worth knowing before you demo.
- No sign-in pages are generated. What the auth UI should look like is a
  product decision; the endpoints above work without one.
